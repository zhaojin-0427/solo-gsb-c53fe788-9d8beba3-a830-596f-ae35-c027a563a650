# 航标灯质可辨性本地 Web 预检台

供航标灯质设计人员使用的**本地** Web 工具：

1. **可辨性预检**：录入 2～20 盏灯的循环亮灭串，穷举任意两盏灯各自独立的
   起始相位，计算前 n 位汉明距离，找出观测窗口上限 W 以内**最短的可辨窗口**；
   W 位仍不可辨时，给出混淆灯对、距离最近的相位组合与逐位差异。全程**穷举
   每一对灯的全部 La×Lb 个独立相位，不抽样、不略过任何相位**。
2. **观测反演**：选择一条已保存分析的冻结快照，提交 1～W 位的实际 0/1 观测
   串与误判上限 e（0～3），服务**穷举快照内每盏灯的全部循环相位**，按前缀
   更新候选集合（累计汉明距离一旦 > e 立即出局）：唯一时给出灯名、相位与
   纠正后的理想序列；多候选时给出每灯候选数、最早无法排除的位置与每灯一条
   见证；无候选时说明原因。反演记录连同所选快照与输入整体冻结，可回看、可
   删除，编辑当前灯串不影响任何历史记录。
3. **灯串修订建议**：选择一条 **W 位不可辨**的冻结分析、指定其中**一盏灯**
   和最多翻转 **1 或 2 位**，服务读取该分析的**快照灯串、W、k** 交给搜索
   引擎：只搜索**仍同时含 0、1 且只改该灯**的翻转方案。每个候选都以
   **全部灯对**各自穷举独立相位后在 **W 位的最小汉明距离均 > 2k** 判定
   （不能只修原混淆灯对）；未改灯对的判定只算一次并复用、逐对精确剪枝。
   裁决顺序为**翻转数最少 → W 位全局最小距离最大 → 翻转位置序列（从 0 起）
   字典序最小**（穷举同翻转数全部候选，不返回首个可行方案）。无解时明确
   提示且**不改工作区**；应用方案时服务端先独立复核，再在 SQLite 事务中
   核对当前整组灯名、灯串及 W、k 与快照完全一致后，**仅替换所选灯串**——
   快照被删除或工作区状态冲突则拒绝且不写入；历史分析与反演记录继续可回看。

- 后端：Python 3.12 · FastAPI · SQLite（NumPy 向量化穷举）
- 前端：原生 HTML / CSS / JavaScript（无构建、无外部 CDN）
- 部署：Docker Compose 一键启动

## 一、启动与访问

### 方式 A：Docker Compose（推荐）

前置：已安装 Docker 与 Docker Compose 插件。

```bash
docker compose up -d --build
```

启动后浏览器访问：

- 应用页面： <http://localhost:8000/>
- 接口文档（FastAPI 自动生成）： <http://localhost:8000/docs>
- 健康检查： <http://localhost:8000/api/health>

停止：

```bash
docker compose down          # 停止，保留数据卷
docker compose down -v       # 停止并删除全部历史数据
```

SQLite 数据库保存在 Docker 命名卷 `beacon-data`（容器内 `/srv/data/beacon.db`），
容器重建不丢历史分析。

### 方式 B：本地直接运行（无 Docker）

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

数据库默认位于 `app/data/beacon.db`（可用环境变量 `DB_PATH` 覆盖）。

## 二、使用流程

1. 左侧维护灯串：每盏灯一个**名称**和一条 **0/1 循环串**
   - 2～20 盏灯；每串长度 2～80 位；必须**同时含 0 和 1**
   - 每位 = **0.1 秒**；整串无限循环，亮（1）/灭（0）
2. 设置参数：
   - **W**：观测窗口上限，1～400（位），即 0.1～40 秒
   - **k**：每段最多误判位数，0～3
3. 点击 **「保存并分析（穷举全部相位）」**。
4. 中间区域查看：
   - 每盏灯的**循环波形**（橙=亮 1，灰=灭 0，虚线为循环串边界）
   - **结论**：可辨时给出最短窗口 n\*（位与秒）；无解时列出在 W 位下仍
     混淆的灯对
   - 每个灯对一张卡片：穷举全部相位后的**最小距离曲线**（n=1..W，
     红色虚线为阈值 2k），以及**决定性窗口下的逐位见证**
5. 右侧为**历史分析**。每次分析都会把当时的灯串、W、k 与完整结果整体
   冻结保存；之后无论怎样编辑灯串或参数，点开旧记录看到的始终是当时的
   结果。「保存灯串/参数」只更新当前设计，不改动任何历史记录。

## 二之二、观测反演使用流程

1. 先确保至少有一条**已保存分析**（反演以该分析的冻结快照为对象，下拉框
   列出全部历史分析）。
2. 在中间面板切换到 **「观测反演」** 标签：
   - **① 选择冻结快照**：下拉展示每条分析的编号、W、k、灯数与可辨结论；
     下方列出该快照的灯名与串长。
   - **② 实际观测串**：1～W 位 0/1，每位 0.1 秒；**误判上限 e**：0～3。
3. 点击 **「反演（穷举快照全部相位）」**。服务对快照内每盏灯穷举其全部
   循环相位（合计 Σ 串长 个，不抽样），逐位读入观测串并按前缀筛除候选。
4. 三种结局：
   - **唯一候选 ✓**：给出灯名、循环串、起始相位、误判位置，以及**纠正后
     的理想序列**（实际观测与理想序列逐位对照，红底标误判位）。
   - **仍有多个候选**：表格列出**每盏灯的候选数**、一条见证相位与距离、
     该灯全部候选相位；下面给出每灯一条逐位见证；并给出**最早无法排除的
     位置**（从该位起读完整个观测串都不会再排除候选；若该位置在观测串之
     外，提示需要继续观测到第 n+1 位）。候选漏斗展示初始总数与每读一位后
     的存活候选数。
   - **无候选 ✗**：说明全部灯、全部相位与观测串的汉明距离均 > e，并给
     出全相位穷举下的最近匹配（灯、相位、距离、差异位）作为原因佐证。
5. 右下 **「反演记录（已冻结）」**：每次反演都把**所选快照副本、观测串、
   e、备注与完整反演结果**整体冻结保存（独立于原分析；即使原分析被删除，
   反演记录仍可回看，下拉中会标注「原分析已删除」）。可逐条回看、删除；
   编辑当前灯串/参数不会影响任何反演记录。

### 反演判定规则

- 快照中某灯串长 L、串为 p，相位 φ（0..L−1，定义同预检：观测第 0 位对应
  循环串下标）下，前 n 位理想序列为 `p[φ], p[φ+1], …`（下标模 L）。
- 逐位读入观测串 o[0..n−1]，对每个相位维护前缀汉明距离

      d_φ(t) = Σ_{s<t} [o[s] ≠ p[(φ+s) mod L]]

  保留条件 `d_φ(n) ≤ e`。因 d_φ(t) 只增不减，某相位一旦在某个前缀
  `d_φ(t) > e` 即永久出局——「按前缀更新候选集合」与最终穷举结果完全
  等价且不遗漏相位。
- 「最早无法排除的位置」= 最后一次成功排除候选的位之后的第一个位
  （1 基）；若读到第 n 位仍在排除却未唯一，则为 n+1（观测串之外）。
- 唯一/无候选结局下该字段为 null（不存在“仍需排除”的位置）。

## 二之三、灯串修订建议使用流程

1. 先有一条 **W 位不可辨（W 内无解）** 的已保存分析。在中间面板切换到
   **「灯串修订」** 标签：
   - **① 选择冻结分析**：下拉只列出 `solvable=false` 的历史分析（可辨分析
     会被接口以 409 拒绝），并展示该快照的 W、k 与 W 位仍混淆的灯对。
   - **② 指定一盏灯**：只允许翻这一盏灯；其余灯串在所有候选中保持不变。
   - **最多翻转位数**：1（只搜 1 位翻转）或 2（先搜 1 位、无可行再搜 2 位）。
2. 点击 **「生成修订建议（穷举全部候选）」**。服务读取该分析的冻结快照
   灯串、W、k，枚举该灯串上全部对应数量的位置组合（翻转为 0↔1），剔除
   翻转后变成全 0 或全 1 的非法灯串。
3. 两种结局：
   - **找到修订建议 ✓**：展示修改前/修改后灯串（黄底标翻转位）、翻转位置
     （1 基序号与对应秒数）、裁决依据、候选评估数，以及**修订后最紧灯对**
     （取得 W 位全局最小距离的那一对灯）在最近相位下的逐位对照。点击
     **「应用此方案到当前灯串」**：服务端先独立复核，再在 SQLite 事务中
     核对当前整组灯名、灯串及 W、k 与快照一致，然后仅替换该盏灯；左侧编辑
     区同步刷新，可直接再次「保存并分析」复验。
   - **无可行修订 ✗**：穷举后不存在满足全部灯对 W 位最小距离 > 2k 的方案，
     页面给出原因；若存在**两盏灯都不是被修订灯**且本就 ≤ 2k 的灯对（只改
     一盏灯在原理上不可能消除），会一并点名。**此结局与未点击应用时都不
     改动任何工作区数据。**
4. 应用的冲突保护：快照已被删除 → 404；快照可辨 / 工作区灯名灯串或 W、k
   与快照不一致 / 提交的翻转方案经复核不是裁决出的可行方案 → 409，且
   **不写入**。历史分析与反演记录均为冻结副本，应用修订后仍可逐条回看。

### 修订搜索与裁决规则

- 设被修订灯原串为 p（长 L），候选串 p′ 由 p 在位置集合 P（|P| = 1 或 2）
  上逐位翻转得到；要求 p′ 仍**同时含 0、1**，且除该灯外其余灯串不变。
- **候选可行**当且仅当：对修订后灯串集合中的**每一对**灯 (a,b)，穷举其
  全部 La×Lb 个独立起始相位在 **W 位**的汉明距离最小值

      dmin_{a,b}(W) = min_{i,j} Σ_{t<W} [a[(t+i) mod La] ≠ b[(t+j) mod Lb]]

  全部严格满足 `dmin_{a,b}(W) > 2k`。即不是只检查原混淆灯对——修订可能
  让原本通过的灯对重新落入混淆，所有灯对都重新穷举判定。
- **复用与剪枝**：两盏灯都不是被修订灯的灯对，dmin(W) 与候选无关，只
  穷举一次并在候选间复用；被修订灯与其余各灯的灯对随候选重算，计算中
  某一对一旦 dmin(W) ≤ 2k 立即判该候选出局（该判定只取决于此灯对，剪枝
  精确、不遗漏）。
- **裁决键**（按优先级）：
  1. 翻转数 |P| 最少（1 位可行则不再考虑 2 位）；
  2. 全部可行候选中 W 位全局最小距离 `min_{a,b} dmin_{a,b}(W)` **最大**；
  3. 上两项并列时，翻转位置序列（从 0 起的升序元组，2 位即 (p₁,p₂)）
     **字典序最小**。

  因此返回的是穷举完同一翻转数全部候选后的最优者，**不是首个可行方案**。
- 应用接口不信任客户端传来的新灯串与距离：服务端按快照与翻转位置重新
  构造 p′ 并重新跑一遍搜索复核，再进入写库事务。

## 三、判定规则

- 对灯 A（串长 La）、灯 B（串长 Lb），设各自起始相位为 i（0..La−1）、
  j（0..Lb−1）。相位定义为“观测到的第 0 位对应各自循环串中的下标”。
- 穷举全部 **La×Lb** 个独立相位组合，对每个窗口长度 n=1..W 计算前 n 位
  汉明距离 d_{i,j}(n)，取最小值

      dmin(n) = min_{i,j} d_{i,j}(n)

- 每段观测容许 k 位被误判为 0、k 位被误判为 1，因此两串在 n 位内**可辨**
  当且仅当

      dmin(n) > 2k

- 所有灯对两两可辨，n 位观测才算可辨。由于前 n 位距离随 n 只增不减，
  最短可辨窗口为

      n* = min { n ∈ [1, W] : 对所有灯对，dmin(n) > 2k }

- 若 W 位仍无解，则展示所有 dmin(W) ≤ 2k 的混淆灯对，并对每对给出其在
  W 位下距离最近的相位组合 (i,j) 与全部差异位（位置从 1 起、对应秒数）。

### 穷举是如何保证不遗漏的

两灯同时提前一位，差异序列只是整体平移一位。全部 La×Lb 个相位组合按
(i−j) mod g（g = gcd(La,Lb)）划分为 g 个等价类，每类 L = lcm(La,Lb)
个成员，同类成员的差异序列彼此恰为循环左移一位的关系。程序把
g 个类 × L 个位移 × W 个时刻一次性张成张量（元素总数恰为
La×Lb×W，与逐相位朴素枚举一一对应），用 NumPy 前缀和向量化求距离；
每张结果卡片都标注实际枚举的相位组合数 `枚举 La*Lb / La*Lb` 及 gcd
等价类数，便于核对。最坏规模（20 盏 × 80 位 × W=400）在普通机器上
数秒内完成。

## 五、HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 当前灯串与 W、k |
| PUT | `/api/lights` | 整批替换当前灯串（不影响历史分析/反演） |
| PUT | `/api/settings` | 更新 W、k（不影响历史记录） |
| GET | `/api/analyses` | 历史分析列表（含可辨结论与 n\*） |

### 灯串修订接口

`POST /api/analyses/{id}/revision-suggest` 请求体：

```jsonc
{ "light_index": 1, "max_flips": 1 }   // 快照内 0 基灯序号；max_flips ∈ {1,2}
```

- 快照不存在 → 404；快照 `solvable=true` → 409；灯序号越界 / max_flips
  非 1、2 → 422。快照本体不会被修改。

返回（有解，节选）：

```jsonc
{
  "found": true,
  "analysis_id": 1,
  "w": 20, "k": 0, "threshold": 0,
  "light_index": 1, "light_name": "灯 B", "max_flips": 1,
  "candidates_evaluated": 7,   // 评估的合法候选数（已剔除翻转后全 0/全 1）
  "feasible_count": 3,         // 其中全部灯对 dmin(W) > 2k 的个数
  "unchanged_blocking_pairs": [],
  "revision": {
    "nflips": 1,
    "flip_positions": [0],          // 0 基
    "flip_positions_1based": [1],
    "pattern_before": "11100000",
    "pattern_after": "01100000",
    "global_min_distance": 2,       // 修订后全部灯对在 W 位的全局最小距离
    "tightest_pair": {              // 取得该全局最小值的灯对与最近相位见证
      "a": 0, "b": 1, "name_a": "灯 A", "name_b": "灯 B",
      "phase_a": 1, "phase_b": 0, "distance": 2,
      "diff_positions": [7, 15], "bits_a": "...", "bits_b": "...",
      "diff_mark": "       ^       ^"
    }
  },
  "selection_rule": "翻转数最少 → W 位全局最小汉明距离最大 → 翻转位置序列字典序最小；……"
}
```

无解时 HTTP 仍为 200，`found=false`，并给出 `reason` 与
`unchanged_blocking_pairs`（未被修订却本就 ≤ 2k 的灯对）；服务不写任何数据。

`POST /api/analyses/{id}/revision-apply` 请求体：

```jsonc
{ "light_index": 1, "flip_positions": [0] }   // 1~2 个互不相同的 0 基位置
```

服务端先按快照与翻转位置重新构造灯串并重跑搜索复核（方案须确为裁决出的
可行修订），再在 `BEGIN IMMEDIATE` 事务中核对当前 lights 整组灯名、灯串
（按顺序）与 settings 的 W、k 同快照逐项一致，然后只 `UPDATE` 该灯一行。
快照删除 → 404；可辨快照、复核失败、灯串/参数不一致 → 409（事务回滚，
不写入）。成功返回 `applied=true`、修改前后灯串与更新后的 `lights`。
